# Contract: Routes & navigation

The public URL surface of the site, and the navigation guarantees the templates must uphold. `base` is the repository name on GitHub Pages (project site), so every path below is served under `/<repo>` in production and at `/` in local dev.

## Route table

| Route | File | Purpose | Requirements |
|-------|------|---------|--------------|
| `/` | `src/pages/index.astro` | Home: profile headline + project cards | US1, FR-001 |
| `/projects/<slug>/` | `src/pages/projects/[slug].astro` | One case study per project | US2, FR-002, FR-003, FR-004, FR-012 |
| `/about/` | `src/pages/about.astro` | Developer introduction + contact channels | US3, FR-008 |
| `/404` | `src/pages/404.astro` | Not-found page | edge case |
| `/sitemap-index.xml` | generated by `@astrojs/sitemap` | Search discovery | best practice |

**Generated slugs (FR-011)**: `/projects/life-simulator/`, `/projects/agenv/`.

## Navigation contract

- Every page carries the shared header (site name → home, link to `/about`) and footer (developer contact links).
- From `/` a visitor reaches **any** project page in **at most one** click on its card — this is SC-002 ("at most 2 interactions").
- Each project card links to its detail page, and (when present) to `repo` and `demo`.
- The about area is reachable from every page (header/footer).
- A broken or unknown path renders the 404 page with a link back to `/`.

## URL stability contract

- A project's URL derives solely from its **filename/slug** and must not change when other content, ordering, or presentation changes (FR-002, "stable, shareable address").
- Renaming a slug is a **breaking change**: it must be accompanied by a redirect/link update (recorded here rather than enforced in code).

## Base-path contract

- All internal links and asset URLs must be generated through Astro's `base`/`import.meta.env.BASE_URL` helpers (or relative links), never hard-coded as root-absolute strings like `/projects/…`.
- Reason: in production the site is served under `/<repo>/`, and root-absolute links would 404 there. This is verified in the deploy checklist.

## Accessibility contract (applies to every route)

- One `<h1>` per page; headings nested without skipping levels; the case-study headings from the content contract appear as `h2`.
- Semantic landmarks (`header`/`main`/`footer`/`nav`), a skip-to-content link, and visible focus styles.
- Text/background contrast meets WCAG AA; images carry `alt` text; links are distinguishable and self-descriptive.
- All interactive elements are keyboard-reachable; no functionality depends on JavaScript (SC-006).
